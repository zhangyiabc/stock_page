# 小说写作流水线

当用户要求写一章新内容时，执行以下标准流程：

## 输入

用户需要提供：
- 章节号（如果是续写，自动取 progress.md 中的下一章）
- 本章简述或关键事件（可选，如果总大纲中已有则自动获取）

## 流程

### Step 1: 上下文收集

使用 `sessions_spawn` 调度 `memory-keeper`：

```
task: "为第{N}章写作准备上下文。请返回：
1. 本章涉及的主要角色当前状态
2. 相关世界设定要点
3. 最近3-5章的摘要（从当前卷分片文件读取）
4. 当前活跃的伏笔列表（特别标出紧迫度高的）
5. 总大纲中本章的规划（如有）
6. 上一章的章末钩子（本章开头需要承接）"
```

### Step 2: 章节规划

使用 `sessions_spawn` 调度 `planner`：

```
task: "为第{N}章创建详细大纲。
章节简述：{brief}
上下文：{Step1的输出}

请产出：
1. 章节结构（3-5个场景，每个场景含情绪基调）
2. 本章爽点设计：
   - 类型（打脸/升级/逆袭/揭秘/捡漏 等）
   - 如何制造压力（先压）
   - 如何引爆（再扬）
   - 读者能获得什么情绪（爽/燃/甜/虐/悬疑）
   - 如果本章无大爽点，说明"推进感"体现在哪里
3. 本章需要埋设/回收的伏笔
4. 章末钩子设计（必须明确，不允许'平着结束'）：
   - 类型（悬念/危机/揭秘/转折/奖励即将兑现）
   - 具体内容描述
5. 本章承接上一章钩子的方式"
```

### Step 3: 正文写作

使用 `sessions_spawn` 调度 `writer`：

```
task: "按照以下大纲撰写第{N}章完整正文。
大纲：{Step2的输出}
上下文约束：{Step1的输出}
目标字数：8000-10000字

特别要求：
- 严格执行大纲中的爽点设计：压得够狠、爆得够爽
- 章末必须有大纲设计的钩子，绝对不能平着结束
- 本章开头需要承接上一章的钩子
- 写完后对照 SOUL.md 禁用词汇清单做全文自检
- 对照 style-guide.md 的每章自检清单逐项检查
- 确认无禁用词命中、限用词未超标、有有效钩子后再提交"
```

### Step 4: 审校

使用 `sessions_spawn` 调度 `editor`：

```
task: "审校第{N}章。
正文：{Step3的输出}
上下文：{Step1的输出}
大纲设计：{Step2的输出}

按优先级检查：
1. AI味检测（禁用词/句式模式/对话自然度）
2. 网文质量检测（爽点执行/章末钩子/节奏/情绪价值）
3. 人物性格和说话方式是否与角色设定一致
4. 是否存在逻辑漏洞和设定冲突
5. 伏笔处理是否合理

输出网文质量评分表和审校报告。
如有严重问题（含AI味/网文质量不合格），输出修订版正文。"
```

### Step 5: 归档

1. 将最终正文写入 `novel/vol{V}/chapter-{NNN}-{章名拼音}.md`
2. 使用 `sessions_spawn` 调度 `memory-keeper`：

```
task: "第{N}章已完成。请执行以下更新：
1. 写入500字章节摘要到对应卷的分片文件 chapters/vol{V}-chapters.md
2. 更新 chapter-log.md 索引中的统计信息
3. 更新涉及角色的状态文件
4. 在 foreshadowing.md 的活跃伏笔表中登记新伏笔，同时写入 vol{V}-planted.md
5. 标记已回收的伏笔，从活跃表移到 archived.md
6. 更新当前卷时间线分片
正文：{最终正文}
审校报告：{Step4中的伏笔记录部分}"
```

3. 更新 `memory/plot/progress.md`
4. 更新 `novel/metadata.md` 中的章节状态索引
