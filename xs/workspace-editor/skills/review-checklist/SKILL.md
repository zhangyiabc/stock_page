# 审校检查清单

执行章节审校时，按以下清单逐项检查。

## 1. AI 味专项检测（最高优先级）

### 词汇层面
- [ ] 搜索 style-guide.md 中的禁用词汇表，如有命中标为 🔴 严重
- [ ] 检查限用词汇（不禁/缓缓/仿佛/然而/就在这时/突然/微微）是否超出每章上限
- [ ] 检查"XX之色"、"眼中闪过一丝"等 AI 高频构式

### 句式层面
- [ ] 是否存在三连排比（"他看到A，看到B，看到C"）
- [ ] 是否存在连续3段以上匀速节奏（每段4-6句，每句15-25字）
- [ ] 是否存在连续段落以相同句式结构开头
- [ ] 是否存在动作后立刻接心理解释的"解释性叙述"
- [ ] 单个名词前是否堆叠超过2个形容词

### 对话层面
- [ ] 角色对话是否过于书面化、完整（应有省略、打断）
- [ ] 是否有角色通过对话"向读者解释"设定/背景（信息倾倒）
- [ ] 不同角色的对话风格是否有区分度

### 结构层面
- [ ] 章末是否有总结/升华/鸡汤式段落
- [ ] 是否存在全知视角泄露（"他不知道的是"、"殊不知"）
- [ ] 第三人称有限视角下是否存在同段内视角跳跃

### AI 味判定标准
- 命中禁用词汇 → 🔴 严重（必须修改）
- 限用词汇超出上限 → 🟡 中等
- 句式/结构模式化 → 🟡 中等（2处以上升级为 🔴）
- 对话不自然 → 🟡 中等
- **AI 味问题超过 5 处 → 整章不合格（VERDICT: FAIL）**

## 2. 网文质量专项检测

### 爽点执行
- [ ] 大纲中设计的爽点是否在正文中被有效实现
- [ ] 压力阶段是否压得够狠——读者是否能替主角感到憋屈/紧张
- [ ] 爆发阶段是否爆得到位——场景感、力量感是否足够
- [ ] 是否存在连续3章以上无任何爽点/推进感（如有标为 🔴）

### 章末钩子
- [ ] 章末是否有有效的钩子（悬念/危机/揭秘/转折）
- [ ] 章末是否"平着结束"（如有标为 🔴）
- [ ] 钩子是否自然——生硬的"强行断章"也是问题

### 节奏
- [ ] 是否存在长段铺垫/描写而无事件推进（超过1000字纯描写/铺垫 → 🟡）
- [ ] 高潮场景后是否回落太久才进入下一个推进（回落超过2000字无新冲突 → 🟡）
- [ ] 本章是否让读者感觉"事情在推进、主角在变化、矛盾在升级"

### 情绪价值
- [ ] 本章提供了什么核心情绪（爽/燃/甜/虐/悬疑/恐惧/治愈）
- [ ] 情绪是否足够明确——如果一章读完读者说不出"什么感觉"，那就有问题
- [ ] 情绪表达是否依赖叙述者告诉读者"他很感动"（应该让读者自己感受到）

### 人物吸引力
- [ ] 主角在本章中是否展现了鲜明特点/标签
- [ ] 反派/对手是否有足够的压迫感和手段（不是只会无脑找茬的工具人）
- [ ] 配角是否有存在感和辨识度

### 信息泄露检测
- [ ] 叙述者旁白是否泄露了后续剧情（"他不知道的是"、"殊不知"、"这个决定将改变"）
- [ ] 主角是否过早推测出了正确真相（对照大纲中的信息控制字段）
- [ ] 角色对话中是否有人"解释太多"——不自然地透露关键信息
- [ ] 反派/配角的动机是否暴露过多（应只展示行为，不解释为什么）
- [ ] 大纲中标注的误导方向是否被正确执行
- [ ] 本章是否同时揭示了多个中层悬念（每章最多揭一个）

### 网文质量判定标准
- 章末无钩子/平着结束 → 🔴 严重
- 连续2章无推进感 → 🔴 严重
- 信息泄露导致主线可被猜透 → 🔴 严重
- 爽点执行不到位（压不够或爆不够）→ 🟡 中等
- 节奏问题（铺垫过长/回落过久）→ 🟡 中等
- 情绪不明确 → 🟡 中等

### 开篇专项（仅前3章）
- [ ] 是否在第1章直接进入冲突/危机
- [ ] 前3章是否交代了：主角是谁、遇到什么麻烦、有什么特别、为什么值得继续看
- [ ] 金手指/特殊优势是否在前3章出现或暗示
- [ ] 是否存在大段旁白式世界观介绍
- 开篇前3章不合格 → 🔴 严重（要求重写）

## 3. 一致性检查

- [ ] 人物性格一致性：角色的行为、反应是否符合其性格设定
- [ ] 人物外貌一致性：体貌特征、穿着是否与之前描述矛盾
- [ ] 对话风格一致性：说话方式是否符合该角色的语言特征
- [ ] 时间线正确性：事件发生的时间顺序是否合理
- [ ] 空间逻辑：地理位置、距离、移动时间是否合理
- [ ] 设定合规：是否违反已建立的世界观规则
- [ ] 伏笔处理：新伏笔是否自然，回收的伏笔是否呼应
- [ ] 章节衔接：与前一章的过渡是否自然

## 输出规范

### 审校报告格式

**⚠ VERDICT 与问题等级的一致性校验（输出前必须自检）：**
- 如果问题清单中存在任何 🔴 → VERDICT 必须是 FAIL
- 如果 VERDICT 是 PASS → 问题清单中不能出现 🔴
- 违反以上规则 = 报告无效

```markdown
VERDICT: PASS/FAIL

# 第X章审校报告

## 总体评价
（一句话）

## 网文质量评分

| 维度 | 评分 | 说明 |
|---|---|---|
| 爽点执行 | ⭐⭐⭐⭐⭐ | 压得够/爆得爽/收获明确 |
| 章末钩子 | ⭐⭐⭐⭐⭐ | 是否让人想翻下一章 |
| 节奏 | ⭐⭐⭐⭐⭐ | 是否有推进感，无冗长段落 |
| 情绪价值 | ⭐⭐⭐⭐⭐ | 核心情绪：{爽/燃/甜/虐/悬疑} |
| AI 味 | ⭐⭐⭐⭐⭐ | 禁用词/句式模式/对话自然度 |
| 设定一致性 | ⭐⭐⭐⭐⭐ | 人设/时间线/世界观合规 |

## 问题清单

### 🔴 严重问题（必须修改）
1. [行X] 问题描述 → 修改建议

### 🟡 中等问题（建议修改）
1. [行X] 问题描述 → 修改建议

### 🟢 轻微问题（仅供参考，不要求修改）
1. [行X] 问题描述 → 修改建议

## 修改要求清单（仅 FAIL 时输出）
（FAIL 时必须逐条列出具体修改要求。PASS 时不输出此段——🟡/🟢 问题是建议性质，不要求 writer 修改。）

## 伏笔记录
- 新埋设：{描述}
- 已回收：伏笔#{ID}
```
